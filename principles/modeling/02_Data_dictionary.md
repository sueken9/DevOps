# データ辞書の原則

## データ辞書とは

システムで扱うデータの意味・値域・制約を定義した辞書。
設計・実装の前に存在し、チーム全体の共通認識の基盤となるドキュメント。

## フェーズごとの定義項目

| フェーズ | 定義項目 |
|----------|------------|
| 要件・分析フェーズ | 論理名、値域、説明 |
| 設計フェーズ | 物理名、型 |
| 実装フェーズ | 制約、初期値など |

## 記述記法

| 記法 | 意味 | 例 |
|------|------|----|
| `＝ [ A \| B \| C ]` | 選択（どれか一つ） | 手 ＝ [ グー \| チョキ \| パー ] |
| `＝ A ＋ B` | 合成（すべて） | 対戦 ＝ プレイヤーの手 ＋ 勝敗結果 |
| `＝ n{ A }m` | 繰り返し（最小n、最大m） | 履歴 ＝ 1{ 対戦記録 }5 |
| `＝ n{ A }n` | 繰り返し（最小n、上限なし） | 履歴 ＝ 0{ 対戦記録 }n |
| `＝ ( A )` | オプション（あってもなくても良い） | — |
| `/* */` | 説明・補足コメント | /* 給湯口をロック解除すること */ |

## 記述ルール

- **論理名**：業務的な意味を持つ日本語
- **論理名**：目的を含めた名前にする（例：「要求」だけでなく「ゲーム進行要求」のように目的を明示）
- **論理名**：特定システム・ドメインの固有名詞を避ける（他のシステムでも再利用できる言葉を選ぶ）
- **値域**：日本語（論理的な定義）

## 他ドキュメントとの整合性

データ辞書は以下すべてのドキュメントと整合していなければならない。

| ドキュメント | 整合すべき内容 |
|------------|--------------|
| コンテキストダイアグラム | データフロー名がデータ辞書の論理名と一致する |
| イベントリスト | 入力・出力がデータ辞書の論理名のみで構成される |
| データフロー図（DFD） | データフローおよびデータストアがデータ辞書に定義されている |

いずれかのドキュメントで新しいデータが出てきたら、データ辞書を更新する。
データ辞書が変わったら、関連するすべてのドキュメントを確認する。

## データ辞書が設計の土台である理由

- 命名の根拠になる
- 仕様変更時の影響範囲が特定できる
- 派生開発で「何が変わったか」を追跡できる
