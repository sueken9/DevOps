# イベントリストの原則

## イベントリストとは

システムに影響を与える外部イベントを一覧化したドキュメント。
コンテキストダイアグラムとデータ辞書の整合性を精査するために使用する。

## 列の定義

| 列 | 定義 |
|----|------|
| No | イベントの識別番号 |
| イベント | 発生する出来事の名称 |
| 発生源 | イベントを引き起こす外部エンティティ |
| 入力 | システムが受け取るデータ（データ辞書の定義と対応） |
| 出力 | システムが返すデータ（データ辞書の定義と対応） |
| 効果 | イベントが利用者・環境・社会に与える影響 |

## 記述ルール

- 「—」は基本的に存在しない。埋まらない場合はイベントの定義が不完全
- 入力・出力はデータ辞書の論理名と対応していなければならない
- 効果はシステム内部の処理ではなく、利用者・環境・社会への影響を記述する

## イベント名の付け方

イベント名は **WHAT（何が要求されたか・何が変化したか）** で命名する。HOW（物理的な動作・行為）で命名しない。

| HOW ✗ | WHAT ○ |
|--------|--------|
| 開閉ボタン押下 | ガレージ開閉要求 |
| 緊急停止ボタン押下 | ガレージ緊急停止要求 |
| 可動域内物体検知 | 物体距離の変化 |
| インターロック操作 | ロック切替要求 |

## イベントの抽象化

同じ発生源・同じ入力データから生じる細かい違いはイベントとして分けない。
データの値（開操作・閉操作・一時停止など）の違いはシステム内部で処理する。
細かく分けすぎると行が増え続け、管理できなくなる。

## 効果の書き方

効果はユーザが得られる**メリット・価値**を記述する。システムの動作説明にしない。

| システム動作説明 ✗ | ユーザへのメリット ○ |
|-----------------|-------------------|
| ガレージ扉が開閉する | 車の出し入れを自由に行える |
| ガレージ扉が緊急停止する | 危険を感じた際に即座に扉を止められる |
| ガレージ扉が緊急停止する | 人・物が扉に挟まれる危険を防げる |

## 出力「—」と要求仕様の関係

出力が「—」になるイベントは、**要求仕様の漏れまたは将来要求の候補**を示している。
現時点では対応しない場合でも、要求仕様に「将来の要求候補」として記録しておく。
