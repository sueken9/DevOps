# 開発フローの原則

## 基本フロー

```
要件定義
  ↓
コンテキストダイアグラム（初版）
  ↓
データ辞書（初版）
  ↓
コンテキストダイアグラム ⇔ データ辞書（整合性確認・相互精査）
  ↓
イベントリスト（外部イベントと入出力の精査）
  ↓
コンテキストダイアグラム ＋ データ辞書（両方を更新）
  ↓
DFD（データフロー図）
  ↓
  ...
```

## ドキュメント間の整合性（三角形）

コンテキストダイアグラム・データ辞書・イベントリストは三つ巴で整合していなければならない。

```
コンテキストダイアグラム
        ↕
データ辞書 ⇔ イベントリスト
```

- コンテキストダイアグラムのデータフロー名 → データ辞書に定義が存在するか
- イベントリストの入力・出力 → データ辞書の論理名のみで構成されているか
- イベントリストの入出力 → コンテキストダイアグラムのデータフローと対応しているか

いずれかのドキュメントを編集したら、**編集完了前に**残り2つの整合を確認・更新する。
「知っている」だけでは不十分。編集アクションのトリガーとして実行する。
