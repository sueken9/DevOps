# コンテキストダイアグラムの原則

## 外部エンティティとは何か

外部エンティティとは、**システム境界の外側に存在する**人・組織・システム・H/Wのこと。

### 外部エンティティの判断基準

| 判断 | 説明 |
|------|------|
| 外部エンティティ ○ | 人間のユーザー、外部API、連携システム、H/Wデバイス |
| 外部エンティティ ✗ | システム内部のロジック・処理（乱数生成、計算、変換など） |

### よくある間違い

**内部処理を外部エンティティとして書いてしまう**
- 例：乱数生成、暗号化処理、キャッシュ → これらはシステム内部

## データフロー名の付け方

データフロー名は **WHAT（データの論理的な意味・目的）** で命名する。HOW（デバイス名・技術名・動作名）で命名しない。

### なぜWHATにこだわるか

| メリット | 説明 |
|---------|------|
| 技術変化への耐性 | 「超音波信号」はLiDARに変えた瞬間に陳腐化するが「物体距離」は変わらない |
| 非技術者とのコミュニケーション | WHATはユビキタス言語になる。ユーザ・企画・エンジニアが同じ言葉で議論できる |

### HOWになる典型パターン

| パターン | HOWの例 | WHATへの修正例 |
|---------|---------|--------------|
| デバイス名をそのまま使う | インターロック信号 | 操作許可有無 |
| 技術名をそのまま使う | 超音波信号 | 物体距離 |
| 動作・方向をそのまま使う | 昇降信号、モータ駆動 | 開閉操作、開閉指示 |
| システムの判断結果を使う | 物体検知信号 | 物体距離 |

### WHATの命名パターン

- **〜有無**：データが存在するかどうか（例：操作許可有無、緊急停止有無）
- **〜距離／〜量**：センサーが計測した値そのもの（例：物体距離）
- **目的を表す名詞**：データが何を意味するか（例：開閉操作、開閉指示、点灯指示）

### 外部エンティティのグループ化

同じ目的・役割のデバイスは1つの外部エンティティにまとめ、データフローも1本にする。
個別のHOW（上昇・下降）を捨て、共通のWHAT（開閉）に抽象化することがデータ設計の本質。

## コンテキストダイアグラムの種類

コンテキストダイアグラムには**要求版**と**ハードウェア版**の2種類がある。

| 種類 | 外部エンティティ | データフロー名の語彙 |
|------|----------------|-------------------|
| 要求版 | 論理的な存在（ユーザー、外部システム） | 〜要求、〜通知など論理的な名前 |
| ハードウェア版 | H/Wデバイス（センサー、スイッチ、アクチュエーター） | 操作、信号、指示など物理的な名前 |

両方を作成することで分析精度が上がる。

### 派生開発での注意点

初版では外部エンティティが少なくても、機能追加で増える。
追加のたびにコンテキストダイアグラムを更新し、**システム境界の変化**を明示する。

外部エンティティが増える典型パターン：
- 外部API連携の追加
- H/Wデバイスとの接続
- 他システムとのデータ連携
