# 命名の原則

すべての設計ドキュメント（コンテキストダイアグラム・データ辞書・イベントリスト・DFD・モジュール構造図）に共通して適用する。

## 責務のない動詞を使わない

以下の動詞は「何をするか」が不明確で、設計要素の責務を表現できていない。

| 使ってはいけない動詞 | 問題 |
|------------------|------|
| 制御する | 何をどう制御するか不明。入力・出力・判断のどれかすら伝わらない |
| 管理する | 何を管理するか不明。CRUDのどれかすら伝わらない |
| 共通する | 動詞になっていない。実装の都合（共通化）を設計名にしている |
| 処理する | 何の処理かが不明。すべてのモジュール・プロセスは何かを処理する |
| 行う | 「何かをする」以上の情報がない |

データ辞書の論理名＋具体的な動詞（取得する・判断する・送る・点灯する・鳴動する・切り替える・検知する）で表現する。

## WHATで命名する

HOW（どうやるか・何の技術か）ではなく、WHAT（何を・何のために）で命名する。

この原則は各ドキュメントの命名規則でも詳細に定義している。

| ドキュメント | 詳細 |
|-----------|------|
| コンテキストダイアグラム | `01_context_diagram.md` — データフロー名の付け方 |
| イベントリスト | `03_event_list.md` — イベント名の付け方 |
| DFD | `04_dfd.md` — プロセスの命名規則 |
| モジュール構造図 | `05_module_structure.md` — モジュール名の命名規則 |
